## ✨ Features

### 🔬 Live heat-transfer simulation
A transient heat-transfer solver written from the governing PDE up, running entirely client-side on a `<canvas>` (`/heatsimulation`):

- **560 × 240 structured grid (134,400 nodes)** stepped with explicit Euler. Diffusion uses a central-difference Laplacian and convection uses first-order upwind differencing.
- **NACA 0012 geometry** from the 4-digit thickness equation, rotated to the chosen angle of attack. The velocity field comes from a potential-flow approximation with circulation.
- **Real-time controls:** thermal diffusivity (0.1–2.0), airspeed (20–300 m/s), surface temperature (300–800 K), angle of attack (−10° to 15°), plus pause, reset, equation overlay, and streamline toggles
- **Live statistics:** average heat flux plus Reynolds, Prandtl, and Nusselt numbers (laminar/turbulent Nusselt correlations)
- **Hover readout** of temperature (K and °C), canvas position, and region, with 300 tracer particles drawn as streamlines
- **Fast rendering:** solver state lives in swapped `Float64Array` buffers, and the colour map is written into one reusable `ImageData`. Each frame is a single `putImageData` call instead of 134,400 `fillRect`s.
- Six KaTeX-typeset equations covering the model, discretization, dimensionless numbers, and airfoil geometry

A companion **case study** at `/projects/heat-transfer` walks through the problem statement, solution approach, technology choices, outcomes, and key concepts.

### 🎨 Animated maze background
A decorative full-viewport canvas behind every page. It lives outside the router, so it persists across navigation.

- A maze generated by recursive backtracking, with extra passages opened to form loops, regenerated every 25 seconds
- Up to 60 particles with fading trails, 20 signal pulses, 15 drifting math symbols, and a rotating î/ĵ/k̂ basis-vector glyph, all scaled to viewport area
- **Throttled to 30 fps**, with device-pixel ratio capped at 2 and debounced resizes
- **Respects `prefers-reduced-motion`**: it paints a single still frame, and reacts if the preference changes mid-visit

### ⌘ Command palette
Press **⌘K / Ctrl+K**, or use the header's search button, to jump anywhere:

- Fuzzy subsequence matching across 11 actions: every page, both heat-transfer pages, GitHub / LinkedIn / X, and "copy email address"
- Keyboard-driven (↑ ↓ ↵ Esc) with focus restored on close, and the shortcut hint adapts to Mac vs. other platforms

### 📬 Working contact form
- MudBlazor form with validation: required fields, email format, and a 10,000-character message limit
- Messages are sent server-side by **MailKit** over SMTP with STARTTLS, with the visitor's address set as `Reply-To`
- Snackbar feedback for success, validation, and failure, with failures logged along with the exception

### 🧑‍💻 About, interests & projects
- **About** toggles between a plain-language **Words** profile and a **Model** view that presents Sam as syntax-highlighted C#: `IDeveloper`, `IAnalyst`, `IMechanicalEngineer`, `IPolicyWonk`, `IGamer`, and `IAudiophile` interfaces, plus a `SamE` class that implements them all.
- **Interests** shows tag cards across six categories, from music and film to electronics.
- **Projects** is driven by `ProjectCatalog`. The featured project gets a large card with an SVG airfoil glyph computed from the same NACA equation, and new catalog entries appear in the grid automatically.

### 🔎 SEO, sharing & accessibility
- Every page is **prerendered**, so search engines and link unfurlers (LinkedIn, X, Slack) receive complete HTML
- A reusable `<Seo>` component emits the title, description, canonical URL, Open Graph, and Twitter card tags (`noindex` on error pages)
- **schema.org `Person`** JSON-LD, `sitemap.xml`, `robots.txt`, a web app manifest, and a social preview image
- Skip link, focus moved to each new page's `<h1>`, and an `inert`-managed mobile drawer with Escape-to-close and focus return
- Text colour tokens meet WCAG AA contrast

### ⚡ Performance
- Static assets are served through **`MapStaticAssets`**. In published builds, fingerprinted URLs get a one-year `immutable` cache and are precompressed with **Brotli and gzip**. The Development server sends `no-cache` and gzip only.
- **KaTeX loads on demand** (from jsDelivr, with SRI hashes) only on the two pages that typeset math, instead of blocking every page's `<head>`
- Variable fonts (one file per family) and `<ResourcePreloader />` for Blazor framework assets

## 🧱 Architecture notes

- **Where code runs.** Pages are Razor components prerendered on the server, then made interactive over a SignalR circuit. The simulation, maze background, and command palette are plain JavaScript that runs entirely in the browser. Blazor only starts and stops the simulation through JS interop (`HeatSimulation.init` / `HeatSimulation.dispose`).
- **Content is code.** There's no database or CMS. Identity, contact details, navigation, and social links live in `Data/SiteInfo.cs`, portfolio entries in `Data/Projects.cs`, and page copy in the `.razor` files.
- **One theme, two places.** Design tokens are CSS custom properties in `app.css`, and `Components/Layout/SiteTheme.cs` mirrors them so MudBlazor components match. Change both together.
- **Stable element ids.** `heatSimulation.js` finds its canvas, sliders, and stat cards by id, so keep those ids unchanged when editing `HeatTransfer.razor`.
- **Aspire is a local-development host.** `samelhag.dev.AppHost` runs the site alongside the Aspire dashboard for logs, traces, and metrics. Production runs the web project on its own. The OTLP exporter turns on only when `OTEL_EXPORTER_OTLP_ENDPOINT` is set.

## 🚀 Getting started

### Prerequisites
- [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0). The Aspire AppHost SDK restores from NuGet, so no workload install is needed.
- Optionally, Visual Studio, VS Code with C# Dev Kit, or JetBrains Rider

### Run locally

```bash
git clone https://github.com/SamElhagDev/samelhag.dev.git
cd samelhag.dev
```

**With the Aspire dashboard** (logs, traces, and metrics):

```bash
dotnet run --project samelhag.dev.AppHost
```

The dashboard opens at `https://localhost:17296`. If the browser doesn't open, use the login link printed in the console. Open the site from the dashboard's resource list. If the browser rejects the certificate, trust the development certificate with `dotnet dev-certs https --trust`.

**Or run the web app directly:**

```bash
dotnet run --project samelhag.dev
```

The site is served at `http://localhost:5264`. Add `--launch-profile https` to also serve `https://localhost:7063`.

### Configure the contact form (optional)

The site runs without email credentials. Until they're configured, form submissions show an error message and log the failure.

Non-secret settings (`Host`, `Port`, `SenderEmail`, `SenderName`, `RecipientEmail`) live under `EmailSettings` in `appsettings.json`. SMTP credentials are read from the `samelhagdevSMTP` configuration section. For local development, keep them in user secrets:

```bash
dotnet user-secrets set "samelhagdevSMTP:Username" "you@gmail.com" --project samelhag.dev
dotnet user-secrets set "samelhagdevSMTP:Password" "your-app-password" --project samelhag.dev
```

With Gmail, use an [App Password](https://myaccount.google.com/apppasswords), which requires 2-Step Verification. In production, supply the same keys as environment variables: `samelhagdevSMTP__Username` and `samelhagdevSMTP__Password`.

### Build and publish

```bash
dotnet build samelhag.dev.slnx
```

```bash
dotnet publish samelhag.dev/samelhag.dev.csproj -c Release -o ./publish
```

## ✏️ Editing content

| To change… | Edit |
|---|---|
| Name, role, email, location, social links, navigation | `samelhag.dev/Data/SiteInfo.cs` |
| Portfolio entries and which one is featured | `samelhag.dev/Data/Projects.cs` |
| Colours, type scale, spacing | `:root` tokens in `wwwroot/app.css` **and** `Components/Layout/SiteTheme.cs` |
| Command palette entries | `ACTIONS` in `wwwroot/js/command-palette.js` |
| Pages submitted to search engines | `wwwroot/sitemap.xml` |

**Adding a page:** create a component with an `@page` route, a `<Seo>` block, and a `<PageHeader>`. Then add it to `SiteInfo.Navigation` (if it belongs in the menu), `sitemap.xml`, and the command palette. The palette's entries are hard-coded in JavaScript, so they don't pick up changes to `SiteInfo`.

## 🚢 Deployment

[`.github/workflows/dotnet.yml`](.github/workflows/dotnet.yml) runs on every push to `main`, on a self-hosted Windows runner that also hosts IIS:

1. Restore, build in Release, and run `dotnet test` (there are no test projects yet, so this step passes trivially)
2. Publish the web project (not the AppHost) to `./publish`
3. Stop the IIS site `SamElhagDev` and the app pool `SamElhag.Dev`, waiting up to 120 seconds for the pool to stop
4. Copy the published output to `C:\inetpub\sites\SamElhagDev`
5. Start the app pool and the site

The server needs the `samelhagdevSMTP` credentials set as environment variables for the contact form to deliver mail.
